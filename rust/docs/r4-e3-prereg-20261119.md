## Evidence and hypothesis

The corrected baseline32 plan is macro **0.4861**, pool **19/25**, selected
**8/25**; the historical best remains **0.5278** and RAG GO is **0.5722**.
E2 attempt 02 scored macro **0.4861**, pool overlap **12/25**, selected **8/25**.
In D12, typed expansion changed the corrected-baseline exact symbol query
`sp_UpdateOrgTotalEmployee` to the generic `CoreService`; D12 had no selected
C#/SQL gold evidence. In D01, only the full controller C1 method was selected;
its required C2 service method was not. E2's structured parent was a whole
class for some fragment candidates. The current `reference_names` uses that
whole class before the existing per-round reference cap, so unrelated sibling
methods can consume the small typed-reference budget. The parent relation is
useful, but it is too broad for call extraction.

**Hypothesis:** for a candidate fragment contained by a parsed C# method or SQL
procedure, derive typed references from only that containing declaration; if no
containing declaration parses, fall back to the validated structured context
range, then to the original candidate. This should preserve actual invocation
and SQL-literal targets (including cross-file procedure lookup) while avoiding
sibling-class noise. It changes only typed-reference scope; it does not change
candidate projection, E2's rank-time declaration containment, ranking weights,
selection quotas, call allocation, budgets, index, corpus, model, plan, or gold.

This is deliberately classified as a **reference/retrieval-scope** experiment,
not proof of a standalone evidence-packing improvement. Report pool/query
changes separately from selected evidence. Do not attribute a gain to
representation alone if it comes from a changed call target or candidate pool.
