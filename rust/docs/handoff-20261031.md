## Daemon/CLI UX V2 implementation checkpoint

Implemented on `work/zg-optimization` after the UX0 checkpoint:

- UX1: management commands default to auto; a ready daemon is selected and
  printed as `route: daemon`, otherwise `route: direct`. `--daemon` forces the
  daemon and `--mode direct` forces direct; `--no-wait` submits an index job
  and prints its id.
- UX2: same-root manual work cancels an active watcher at its next safe
  checkpoint, then runs as the single follow-up writer. Watcher events during
  the manual job are coalesced and resume after success, failure, or
  cancellation; no second writer is created.
- UX3: `JobView` now publishes `priority`, `queue_position`, and `cancelable`;
  `zg --server jobs` renders them; `zg --server cancel <id>` requests
  cancellation. Scheduler lanes are configurable (`manual_concurrency`,
  `watch_concurrency`, `queue_capacity`).
- UX4: `results/` is now a default ignored directory alongside generated/build
  and cache trees. Index summaries report skipped counts and bounded samples;
  watcher jobs do not replay one-operation scan overrides.
- Wait timeout: `a_timed_out_waiter_does_not_cancel_the_running_job`.
- Real watcher flow: `real_watcher_and_default_manual_rebuild_resume` starts a
  real daemon/watcher, writes before/after files, and runs a default manual
  rebuild between them.
- Daemon stop: `daemon_stopped_before_default_index_falls_back_direct_without_hanging`.
- Default-flow proof: `default_index_routes_to_ready_daemon_and_falls_back_direct`
  runs the real CLI with no mode flag and checks `route: daemon` against a live
  daemon plus the daemon job transition. Combined with the scheduler supersede
  tests, this proves UX1 feeds UX2 in the normal operator flow.
- Lock proof: `daemon_watcher_and_direct_writer_share_the_same_home_lock` asserts
  the watcher and direct CLI contend on the same `locks/home` write lock.
- Regression: `watcher_changes_survive_manual_success_failure_and_cancellation`
  covers all three manual terminal states. The legacy cross-lane queue-pressure
  freshness test was rewritten as
  `watcher_batch_runs_on_its_lane_while_manual_blocks_another_root`.
