## Hypothesis and single change

E1 used `content_range` both as the evidence candidate anchor and as the input
scope for typed-reference extraction. The observed query drift shows those
roles are not interchangeable: a fragment can be a good evidence anchor while
omitting identifiers needed to find callers, procedures, or related
references elsewhere in the enclosing entity.

**E2 hypothesis:** Keep each candidate and selected evidence anchored to the
retrieved fragment range, but use its original enclosing entity range only as
the typed-reference extraction scope. This should preserve E1's precision
boundary without changing the typed-reference query set merely because the
selected evidence unit is narrow. It may improve selected recall by restoring
useful symbol lookups, but the direction is not assumed.

Only the optional parent-reference-range lookup is new. Search queries, returned
backend order/scores, plan, rank weights, selection policy, caps, corpus/index,
model, and source verification remain fixed. The default source implementation
returns no parent scope, preserving existing behavior for all other callers.
