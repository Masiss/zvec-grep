The root-owned attestation `/var/tmp/m4-native-workspace-quota-pwd.attestation.json` binds filesystem UUID `6c15377e-2602-4870-96ba-50e58605309c`, workspace path `research/m4-native/.work/m4-native-workspace-quota`, subvolume/qgroup `259` / `0/259`, and the 134,217,728-byte cap. The workspace has no visible children; no M4 benchmark process or `m4-contained-*` user unit is active.

Although `btrfs qgroup show` and `btrfs subvolume show/list` fail with `Operation not permitted`, the kernel sysfs counters are readable at `/sys/fs/btrfs/<UUID>/qgroups/0_259/`. They report `enabled=1`, `mode=squota`, `inconsistent=0`, `referenced=129,359,872`, `max_referenced=134,217,728`; therefore the live limit-accounting headroom is **4,857,856 bytes**. This is not `du` or `df` inference: it is the live qgroup counter used by the configured hard limit. It is below the first dictionary file size, `jieba.dict.utf8` (**5,071,207 bytes**) by at least 213,351 bytes (and does not include directory/metadata overhead); the two immutable dictionary inputs total 5,590,946 bytes. The failed control arm's `Disk quota exceeded` during that exact snapshot write is therefore explained by insufficient live qgroup headroom, not filesystem-wide free space (26.7 GB was available).

The directory is empty and no old operation root remains in the workspace, so there is no visible owned scratch artifact safe to clean. The sysfs qgroup counter is authoritative for the enforced budget, but `squota` charges extents to the subvolume that first allocated them and does not provide reliable shared/exclusive ownership or physical-reclaimability attribution. Official semantics: [btrfs-quota(8), “Simple quotas (squota)”](https://btrfs.readthedocs.io/en/stable/btrfs-quota.html). Because subvolume listing is denied, this session cannot determine whether snapshot/deleted-subvolume references retain those extents or identify an exact cleanup target; do not infer that the reported `exclusive` value proves no snapshots. No snapshot, cap, or filesystem state was changed.

The snapshot lifecycle in `src/index.cc` is process-local and content-addressed: concurrent analyzers with the same dictionary identity share one directory through leases; the last lease removes it. Thus this is not repeated duplication per index within one process, but separate benchmark arm processes recreate the 5,590,946-byte immutable copy under their own quota-backed `TMPDIR`. A persistent on-disk cache would itself need at least that initial allocation and would retain scratch; reusing one process across arms would change isolation and attribution. A memory-backed redesign could reduce disk writes but would not create the roughly 35 MiB scratch space observed for a full-size operation. No such lifecycle change is justified as a fix for the present capacity deficit.

The previous quota verifier checked only attestation, subvolume identity, and configured cap, so a fresh valid attestation could pass while usable headroom was below the dictionary minimum. It now reads the live sysfs qgroup counters and fails closed unless the configured **64 MiB minimum-free reserve** is available. That reserve exceeds the largest prior sampled 1,200-file workspace peak (34,689,024 bytes) with margin; sampled peaks remain telemetry, not a guaranteed lifetime bound, and the hard 128 MiB quota remains the actual containment limit. Unit tests cover normal counters and insufficient headroom (71 contention-policy tests, 30 benchmark-policy tests, and 14 profiler tests pass); the containment-runner integration suite passes 17/17. The added stats-event zero-net regression passes `m4_correctness` in both normal and ThreadSanitizer builds. Read-only inspection found no visible operation roots, open deleted files, active M4 unit/process, or configured Snapper/Timeshift/Btrfs snapshot timer. This does not rule out manually managed snapshots or deleted-subvolume references. `squota` is first-allocator accounting; its counters do not tell this unprivileged session which extents are held or safely reclaimable. No snapshot/cleanup action can be justified from current evidence.
