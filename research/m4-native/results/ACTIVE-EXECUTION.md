### Flush publication staging — correctness complete; reader-through-flush effect measured once

`research/m4-native/src/index.cc` now stages stats-log append, tombstone-file write, and atomic manifest write while the query mutex is unlocked. The writer-state mutex remains held throughout: the delta/WAL prefix cannot change. After the durable manifest succeeds, the code takes the query mutex once to publish runs, tombstones, manifest, and delta reset as one in-memory transition; it then releases the query mutex for WAL reset and GC. This preserves the durable ordering `segment → stats → tombstones → manifest → in-memory publication → WAL reset → GC`, while keeping readers on the old complete view until publication. Retired delta/run/tombstone allocations are destroyed outside the query lock.

`AppendStatsEvents` now tracks an appended prefix of pending stats events and rolls back partial writes. This is necessary because an unsuccessful flush can be followed by more writes before retry; retry appends only the new suffix instead of duplicating stats events. No writer is admitted during the flush, and same-PK update/delete plus a second flush block behind the state mutex. **This is not concurrent flush and does not reduce writer-state serialization.** A source-level design review rejects unlocking the writer-state mutex in the current representation. `Wal::Reset()` truncates the whole stream, while writers would append a newer suffix; simply releasing the lock would therefore lose durable records. Unlike `MergeRuns`' snapshot rebase (which pins immutable run inputs and leaves the active delta/WAL path intact), flush converts mutable delta state into a run and resets that delta. Correct concurrent flush would require frozen+active delta generations visible together to queries, a durable WAL-prefix/suffix rotation or equivalent, coherent stats/tombstone/PK snapshots, atomic generation publication, and single-flight ownership for overlapping flushes. This is a storage/recovery and query-representation change, not a small lock-scope refactor. Defer that prototype until a measured result shows the remaining state-lock hold justifies its complexity; keep the simpler query-lock publication staging.
