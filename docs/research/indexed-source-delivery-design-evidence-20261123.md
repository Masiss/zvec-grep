## Sol design challenge 2

Verdict: **`APPROVE_DESIGN`** to test C in the isolated experiment; this is not adoption. Sol preferred bounded neighbor expansion over A because it preserves the demonstrated baseline item and avoids globally trusting vector scores on the basis of one rescue. It said A is deterministic only under a verified higher-is-better vector-score contract and remains too risky as primary. Do not combine A and C.

Frozen C policy: produce and reserve the unchanged baseline pack first; keep baseline entity order, identities, and intervals. For each selected fragment ordinal `n`, freeze only `n−1` and `n+1` from that same indexed entity; skip missing neighbors. Process baseline items by final rank, previous neighbor then next. Merge half-open ranges only when they overlap or touch; do not bridge gaps. Charge exact incremental source bytes, including duplicate bytes across different items, and accept a widening only if total stays at or below 24,576. Keep at most 10 items and never displace baseline evidence. No recursion, cross-entity expansion, whole-entity fallback, relevance reranking, model calls, or query-dependent side selection.

Verify the same source snapshot and full-file hash before using neighbor coordinates. Read merged bytes directly from that source, preserve encoding and line endings, recompute content SHA and byte/line coordinates, and preserve full-file SHA only after verification. Skip an invalid neighbor while retaining a valid baseline item; fail if the baseline itself cannot satisfy integrity. Assert baseline interval containment and equality between each delivered item and its declared source slice.

- **S1 — entry-point discovery:** target-file rank and accepted-range rank differ materially on val-02 and val-03, and the rank order differs across methods on several other tasks. The exact source joins validate that val-03's hybrid entity internally owned relevant sibling fragments, but its delivered first fragment did not overlap either accepted range; hidden candidate evidence cannot help a navigator. - **S3 — answer correctness:** not measured. No answer model was run, and neither relevance nor range overlap proves an answer is correct.
- **Baseline fairness:** R4 and `rg` shared the same exact 1,279-file `.cs` source universe, three pinned public revisions, verbatim prompts, 10-item and 24,576-source-byte limits, and adjudication. R4 used its frozen hybrid route with no manual expansion. The lexical arm was a strong fixed workflow: unique question terms (length ≥3, stop list), whole-word case-insensitive OR, merged nine-line windows, and deterministic term-coverage ranking. C's 0.31 s / 82,744 KiB is packer batch overhead, not integrated serving cost. The frozen 24 KiB pack tests one-shot context sufficiency; it does not measure the effort or cost of later source navigation.
